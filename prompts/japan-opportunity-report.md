# Japan Opportunity Report

## Purpose

回答一个问题：

> 是否存在值得研究、并且可以与当前持仓比较的日本股票机会？

本 prompt 用于把日本股票机会放入 IOS 框架中，结合日本市场结构、新 NISA 约束、交易单位、公司治理、股东回报、产业政策和长期企业质量，判断其是否值得进入研究流程。

它不负责生成每日信息过滤。

它不负责维护当前组合。

它不负责进行广义全球机会筛选。

它不负责进行完整组合健康审计。

它不负责给出短期交易信号。

## Investor Profile

适用于以下投资者：

- 生活在日本；
- 使用新 NISA；
- 投资期限为十年以上；
- 以企业所有者心态进行长期投资；
- 偏好集中组合；
- 质量优先；
- 关注 AI Infrastructure、Semiconductors、Cloud、Enterprise Software、Industrial AI、Robotics、日本工业龙头；
- 忽略短期交易。

## Inputs

输入应尽量包括：

- 报告日期或报告周期；
- 当前日本持仓；
- 当前全球核心持仓；
- 日本观察名单；
- 待评估的日本公司；
- 日本市场变化；
- TOPIX 或 Nikkei 背景；
- 日本行业轮动；
- 盈利预期变化；
- 分析师上调或下调；
- 公司治理变化；
- 回购、分红、交叉持股、资产出售或资本配置更新；
- 日元、利率、通胀和工资背景；
- 产业政策和供应链趋势；
- 交易单位、碎股或最低买入金额限制；
- 新 NISA 额度和账户约束；
- 企业质量、竞争优势、现金流、成长、估值和风险证据；
- 与现有日本持仓或全球核心持仓比较所需的信息。

如果输入不足，先标记信息缺口。

不要虚构公司事实、估值、交易单位、持仓、现金或市场数据。

## Output Specification

输出使用以下结构：

```text
# Japan Opportunity Report

## 1. 日本机会结论

## 2. 候选机会

## 3. 日本特定约束

## 4. 企业质量评估

## 5. 治理与资本配置

## 6. 与现有持仓比较

## 7. 新 NISA 适配性

## 8. 风险与排除理由

## 9. 下一步
```

### 1. 日本机会结论

用三到五条 bullet 回答本期是否存在值得研究或比较的日本股票机会。

结论必须使用以下判断语言：

- 没有有吸引力的日本专项机会；
- 继续关注当前持仓；
- 加入日本观察名单；
- 启动研究；
- 与现有日本持仓比较；
- 与全球核心持仓比较；
- 因证据不足延后；
- 排除。

如果日本机会没有明显通过质量、估值和组合比较，应明确写：

> 暂无足够证据证明该日本机会值得优先占用研究时间或新 NISA 额度。

### 2. 候选机会

列出本期值得记录的日本候选机会。

每个候选应包含：

- 公司名称；
- 股票代码；
- 所属市场；
- 所属行业；
- 所处价值链位置；
- 机会来源；
- 触发关注的事实；
- 初步判断；
- 当前状态。

当前状态只能使用：

- 观察；
- 启动研究；
- 与日本持仓比较；
- 与全球核心持仓比较；
- 延后；
- 排除。

### 3. 日本特定约束

日本机会必须先经过本土市场约束检查。

检查项目包括：

| 约束 | 需要回答的问题 |
| --- | --- |
| 新 NISA | 是否值得占用长期免税额度 |
| 交易单位 | 最低买入金额是否影响仓位管理 |
| 流动性 | 是否适合长期组合执行 |
| 汇率 | 日元因素是否改变长期回报判断 |
| 利率与通胀 | 是否影响企业定价权、成本和估值 |
| 公司治理 | 治理变化是否真实改善资本效率 |
| 股东回报 | 分红和回购是否可持续 |
| 产业政策 | 是否支持长期需求，而非短期补贴 |
| 供应链位置 | 是否具备全球竞争力 |

约束检查不得替代企业质量评估。

### 4. 企业质量评估

按 IOS 顺序评估日本企业质量：

```text
产业与价值链位置
↓
企业质量
↓
竞争优势
↓
管理层
↓
资本配置
↓
自由现金流
↓
长期成长
↓
估值
↓
新 NISA 适配性
↓
组合替代性
```

每一项评估应说明：

- 已知事实；
- 初步判断；
- 与全球优秀企业相比是否有竞争力；
- 仍需验证的关键问题。

不得因为公司属于日本、估值较低、分红率较高或回购增加，就直接判定为长期机会。

### 5. 治理与资本配置

单独评估日本企业的治理改善和资本配置。

必须区分：

- 治理改善是否真实；
- 资本效率是否提高；
- 交叉持股是否下降；
- 低效资产是否被处理；
- 回购是否在合理估值下进行；
- 分红是否由自由现金流支持；
- 股东回报是否牺牲长期再投资；
- 管理层是否持续提高 ROIC。

治理改善是加分项，不是充分条件。

如果企业本身缺乏竞争优势，应写明：

> 治理改善不能替代企业质量。

### 6. 与现有持仓比较

日本机会必须同时接受两类比较：

- 与现有日本持仓比较；
- 与全球核心持仓比较。

比较维度包括：

| 维度 | 日本候选 | 现有日本持仓 | 全球核心持仓 | 初步结论 |
| --- | --- | --- | --- | --- |
| 企业质量 |  |  |  |  |
| 竞争优势 |  |  |  |  |
| 管理层 |  |  |  |  |
| 资本配置 |  |  |  |  |
| 自由现金流 |  |  |  |  |
| 长期成长 |  |  |  |  |
| 估值 |  |  |  |  |
| 新 NISA 适配性 |  |  |  |  |
| 理解深度 |  |  |  |  |
| 组合角色 |  |  |  |  |

比较结论应回答：

- 是否优于继续研究现有日本持仓；
- 是否值得与全球核心持仓竞争资本；
- 是否只是日本本土暴露，而不是优秀企业暴露；
- 是否值得进入正式研究流程。

### 7. 新 NISA 适配性

新 NISA 是长期免税复利账户。

必须检查：

- 是否愿意持有十年以上；
- 企业质量是否足以进入长期账户；
- 股东回报是否可持续；
- 交易单位是否导致仓位过大；
- 是否存在为了使用额度而降低标准的风险；
- 是否应先放入观察名单，而不是直接进入行动阶段。

不得因为股票在日本上市、分红较高或便于购买，就认为适合新 NISA。

### 8. 风险与排除理由

记录每个日本机会的主要风险。

风险类型包括：

- 企业风险；
- 估值风险；
- 竞争风险；
- 周期风险；
- 汇率风险；
- 治理风险；
- 资本配置风险；
- 交易单位风险；
- 新 NISA 机会成本；
- 行为风险。

排除理由应具体、可复核。

常见排除理由包括：

- 企业质量不足；
- 竞争优势不清晰；
- 治理改善无法持续；
- 股东回报缺乏现金流支持；
- 低估值只是价值陷阱；
- 交易单位导致仓位不合理；
- 新 NISA 机会成本过高；
- 与现有日本持仓相比没有优势；
- 与全球核心持仓相比没有优势；
- 证据不足。

### 9. 下一步

输出清晰的下一步动作。

允许的动作包括：

- 不采取行动；
- 继续关注当前持仓；
- 加入日本观察名单；
- 启动研究；
- 与现有日本持仓比较；
- 与全球核心持仓比较；
- 等待更多证据；
- 排除。

不得输出买入、卖出、加仓、减仓等交易指令。

## Rules

必须遵守以下规则：

- 只回答“是否存在值得研究、并且可以与当前持仓比较的日本股票机会”。
- 日本机会必须接受与全球机会相同的质量标准。
- 日本机会必须与现有日本持仓和全球核心持仓比较。
- 新 NISA 是长期复利账户，不是交易账户。
- 交易单位和最低买入金额必须进入判断。
- 治理改善、分红、回购和低估值都不能单独构成投资理由。
- 不生成每日信息过滤。
- 不生成周度组合维护报告。
- 不生成广义市场机会报告。
- 不生成完整组合健康审计。
- 不生成 IPO 观察。
- 不给出短期交易建议。
- 不做短期价格预测。
- 不因为日本本土属性、NISA 便利或市场热度提高机会等级。
- 不新增投资哲学。
- 不引入 Book 之外的新框架。
- 不虚构缺失数据。
- 无法判断时，明确标记为“信息不足”。

判断优先级必须保持：

```text
企业质量
↓
竞争优势
↓
管理层
↓
资本配置
↓
自由现金流
↓
长期成长
↓
估值
↓
日本特定约束
↓
组合替代性
↓
执行纪律
```

可使用的结论语言仅限：

- 没有有吸引力的日本专项机会；
- 继续关注当前持仓；
- 加入日本观察名单；
- 启动研究；
- 与现有日本持仓比较；
- 与全球核心持仓比较；
- 因证据不足延后；
- 排除。

## Quality Checklist

输出前必须检查：

- 是否只围绕日本股票机会；
- 是否体现新 NISA、交易单位、日本市场结构和治理改善；
- 是否没有变成日报、周报、广义机会报告、组合健康审计或 IPO 观察；
- 是否没有给出短期交易建议；
- 是否没有因为日本本土属性降低投资标准；
- 是否没有把分红、回购、低估值或治理改善当作充分条件；
- 是否同时比较现有日本持仓和全球核心持仓；
- 是否明确说明证据和信息缺口；
- 是否没有新增投资哲学或新框架；
- 是否符合 IOS 的长期投资顺序；
- 是否保持模型中立；
- 是否可以被 Agent 层稳定调用；
- 是否更新版本记录。
