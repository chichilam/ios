# Daily Investment Report

## Purpose

回答一个问题：

> 今天发生了什么，值得长期投资者记录或继续跟踪？

本 prompt 用于把日常市场信息放入 IOS 框架中，区分长期重要信号和短期噪音。

它不负责给出买卖建议。

它不负责完成企业分析、估值、组合复盘或机会报告。

## Investor Profile

适用于以下投资者：

- 生活在日本；
- 使用新 NISA；
- 投资期限为十年以上；
- 以企业所有者心态进行长期投资；
- 偏好集中组合；
- 质量优先；
- 关注 AI Infrastructure、Semiconductors、Cloud、Enterprise Software、Industrial AI、Robotics、日本工业龙头；
- 忽略短期交易。

## Inputs

输入应尽量包括：

- 日期；
- 今日主要新闻或市场事件；
- 相关公司、行业或资产；
- 价格、估值、利率、汇率或流动性变化；
- 财报、管理层发言、监管变化或产业链信息；
- 已有持仓或观察名单相关事项；
- 任何需要后续验证的假设。

如果输入不足，先标记信息缺口。

不要虚构事实。

## Output Specification

输出使用以下结构：

```text
# Daily Investment Report

## 1. 今日结论

## 2. 长期重要信号

## 3. 短期噪音

## 4. 需要更新的研究事项

## 5. 需要记录但不行动的事项

## 6. 风险提示

## 7. 下一步
```

### 1. 今日结论

用三到五条 bullet 总结今天真正值得长期投资者注意的内容。

如果没有长期重要信号，明确写：

> 今日没有足以改变长期判断的信息。

### 2. 长期重要信号

只记录可能影响十年以上长期价值创造的事项。

每一条信号应包含：

- 事件；
- 涉及的公司或行业；
- 可能影响的 IOS 层级；
- 为什么可能具有长期意义；
- 需要继续验证什么。

IOS 层级包括：

- 企业质量；
- 竞争优势；
- 管理层；
- 资本配置；
- 自由现金流；
- 长期成长；
- 估值；
- 市场环境；
- 行为纪律。

### 3. 短期噪音

记录不应驱动行动的信息。

常见噪音包括：

- 单日股价波动；
- 短期市场情绪；
- 没有新事实的目标价变化；
- 与长期价值创造无关的新闻；
- 无法验证的市场传言。

### 4. 需要更新的研究事项

列出需要进入研究体系的事项。

使用以下分类：

- 观察名单；
- 研究候选；
- 组合候选；
- 估值假设；
- 风险假设；
- 暂不处理。

### 5. 需要记录但不行动的事项

记录应该留痕、但不应触发交易的事项。

每一条应说明：

- 为什么记录；
- 为什么不行动；
- 未来什么信息会改变判断。

### 6. 风险提示

只记录与长期投资纪律相关的风险。

风险类型包括：

- 企业风险；
- 估值风险；
- 组合风险；
- 行为风险；
- 系统风险。

### 7. 下一步

输出下一步动作，但不得直接给出买卖指令。

允许的动作包括：

- 记录；
- 忽略；
- 更新研究笔记；
- 加入观察名单；
- 推进研究候选；
- 更新估值假设；
- 等待更多证据；
- 交给周度复盘。

## Rules

必须遵守以下规则：

- 只回答“今天发生了什么值得长期投资者注意”。
- 默认不交易。
- 不给出买入、卖出、加仓、减仓建议。
- 不做短期价格预测。
- 不把新闻热度等同于企业质量。
- 不把市场情绪等同于长期趋势。
- 不把单日价格变化写成投资结论。
- 不完成完整企业分析。
- 不完成完整估值。
- 不进行组合权重调整。
- 不生成周报。
- 不生成机会报告。
- 不生成 IPO 报告。
- 不新增投资哲学。
- 不引入 Book 之外的新框架。
- 不虚构缺失数据。
- 无法判断时，明确标记为“信息不足”。

判断优先级必须保持：

```text
企业质量
↓
竞争优势
↓
管理层
↓
资本配置
↓
自由现金流
↓
长期成长
↓
估值
↓
市场环境
↓
短期价格
```

## Sheet Write Contract

当结果写入 v2.1 Google Sheets 报告表时，必须严格遵守 `setup/schema/sheet-schema.json`：

- `报告持仓.资产类型` 只允许精确值 `holding` 或 `watchlist`。
- 当前持仓行必须写 `holding`；观察名单行必须写 `watchlist`。
- 严禁写 `持仓`、`观察名单` 或其他本地化/展示文案到 `资产类型` 字段。
- 写入后必须重新读取本次 `(报告ID, 生成ID)` 的 `报告持仓`，逐行验证 `资产类型` 仅包含 `holding/watchlist`；发现其他值时本次写入不得视为成功，必须原位修正后再次验证。

### 观察候选建议动作（报告持仓.IOS状态）

对每个 资产类型=watchlist 的新报告行，IOS状态 是由报告生成阶段给出的 canonical 建议动作，且只能使用以下精确值：

- 研究建仓：值得正式研究是否建立初始仓位，不等于立即买入；
- 等待估值：企业逻辑有吸引力，但估值研究或锚点尚不足；
- 等待价格：研究结论基本成立，但当前价格纪律不满足；
- 继续观察：保留候选，尚未达到建仓研究阶段；
- 降低优先级：相对现有持仓或其他候选机会成本较差。

优先级、价格位置、IOS状态 是三个独立字段：不得用一个字段替代、推导或改写另一个字段。Daily 只根据既有 IOS 研究状态和当日新增证据更新此动作；它不进行完整估值、组合配置或交易决策，也不输出买卖数量。

### 入场计划评估（报告持仓.执行状态，第 298 号 issue）

`入场计划` 是 Deep Dive 拥有的持久化执行计划（长期估值锚点、说明区间占比分母的 计划新增仓位说明、
分批入场区间、技术确认条件、不追高条件、失效条件）。Daily **只读取和评估**这个计划，绝不创建、
修改或重新估算它的任何字段——制定和实质性更新计划是 Weekly Deep Dive 的职责，不属于 Daily 边界。

**活跃计划的选取与并列版本**：一个 `代码` 应该只有一行 `状态=active`；如果因为写入顺序的短暂重叠
意外看到多行，取 `版本` 数字最大的那一行。如果最高 `版本` 本身出现并列（两行或以上 `状态=active`
且 `版本` 相同——这不是正常的写入重叠，因为一次正常的新版本切换总是版本号不同，出现并列说明数据
本身有异常），先用 `数据时间` 更晚的那一行做决胜；如果 `数据时间` 也无法区分，这个 `代码` 视为
"本次无法可靠确定活跃计划"：下面五个评估字段全部留空/留假（等同于没有活跃计划），并写一条
`报告待办`（跟进类型=可执行）说明该 `代码` 的 `入场计划` 存在并列版本需要人工核查清理，绝不能凭
行顺序或猜测选择其中一行，也不设 `需要复核=true`（见下方字段说明）。

如果某个当前持仓或高优先级观察名单条目存在按上述规则确定的活跃 `入场计划` 行，用本次读取到的当前
价格与该计划的区间/条件比较，把评估结果写入 `报告持仓`：

- `入场计划ID`：本次评估所依据的 `计划ID`。
- `入场计划估值锚点`：把该计划版本自己的 `长期估值锚点` **原样复制**进这个字段——不得改写、概括
  或重新表述。这是历史安全的快照：Dashboard 只读取这个快照字段渲染，绝不会反过来去 `入场计划`
  里现查。
- `执行状态`：只能是以下五个精确值之一，按固定优先级顺序判定（条件可能同时满足多个，此时必须按
  顺序取第一个命中的，不是五个互斥的独立判断）：
  1. 计划的 `失效条件`（或 `计划复核触发` 的时效规则）已被触发 → `暂停复核`。优先级最高，不管
     价格此刻是否落在某个入场区间内都覆盖其他判断——这只是"停下来重新评估"的信号，不是自动卖出
     指令，也不能因为价格只是正常回落到计划区间以下就写成这个值。
  2. 价格落在某个入场区间内，且 `不追高条件` 被触发 → `等待价格`。一个被追高条件覆盖的区间内价格
     不能写成"可以开始"，也不属于"等待确认"（不追高条件是价格/时机维度的独立否决条件，优先级高于
     技术确认条件）。
  3. 价格落在某个入场区间内，未被不追高条件否决，但计划设定了 `技术确认条件` 且尚未满足 →
     `等待确认`。
  4. 价格落在某个入场区间内，未被不追高条件否决，且没有未满足的技术确认条件（或计划本身没有设置
     技术确认条件）→ `可小额开始`，可以按该档占比开始执行。
  5. 价格不在任何入场区间内：明显高于或低于全部区间且未触发失效条件 → `等待价格`；价格虽不在区间
     内但接近某个区间边界 → `接近区间`（这是一个研究判断，不是固定数值阈值）。
- **执行状态写入契约**：非空 `执行状态` 只能是上列五个精确值之一；`进入区间`、`不追高`、`暂停并复核`、`无 active 计划` 都不是允许值。不得把价格/技术条件（包括“不追高”）或“没有计划”的事实当作状态写入；没有可靠确定的活跃计划时应按下方规则留空，未命中入场区间时按上列优先级写 `等待价格` 或 `接近区间`。
- `当前区间`：价格所在的具体区间，或不在任何区间内时的简短说明。
- `需要复核`：这是 Weekly 才需要主动判断并配上 报告待办 的字段；Daily 通常留空，不必自行判断计划
  是否需要 Deep Dive 复核。这个字段只针对一个已经可靠选定的具体计划版本——遇到上面"并列版本、
  无法可靠确定活跃计划"的情形时，不适用这条规则，绝不设为真；那种情形改用一条独立的 报告待办 上报
  异常，不通过 需要复核 传递。

写入这五个字段时，必须按下面三种情况精确区分，不能笼统地"缺什么就留空"：

- **没有可用的活跃计划**（`入场计划` tab 不存在、该 `代码` 没有任何 `状态=active` 行）：
  `入场计划ID`/`入场计划估值锚点`/`执行状态`/`当前区间`/`需要复核` 五个字段全部留空，继续只写
  `参考买入价/区间`/`价格位置`，和这个功能存在之前完全一样。
- **活跃计划已经可靠选定，但本次缺少用于评估的市场数据（例如当前价格）**：`入场计划ID` 和
  `入场计划估值锚点` 仍然必须按该计划版本写入——这两个字段只取决于"选中了哪个计划版本"，不依赖
  当前价格；只有 `执行状态`/`当前区间` 因为无法评估而留空；`需要复核` 通常留空（Daily 不必自行
  判断）。绝不能因为价格缺失就连 `入场计划ID`/`入场计划估值锚点` 也一起清空——那会让 Dashboard
  退回到旧的 `参考买入价/区间` 显示，和一个真实存在的活跃计划互相矛盾。
- **活跃计划因并列最高版本无法可靠选定**（见上方"活跃计划的选取与并列版本"）：五个字段全部
  留空/留假，形状上和"没有可用的活跃计划"完全一样；异常只通过一条 报告待办 上报，绝不设
  `需要复核=true`。

**暂存回读与发布门槛**：在切换 `报告摘要` 前，必须重新读取本次暂存的每一行 `报告持仓.执行状态`；每个非空值都必须属于 `可小额开始`/`接近区间`/`等待价格`/`等待确认`/`暂停复核`。若发现别名或任何其他值，必须在同一 `生成ID` 内按上列优先级改正后重新校验；校验仍不通过时不得切换 `报告摘要`，也不得发送成功通知。

源数据（当前价格等）缺失只影响 `执行状态`/`当前区间`，不得据此推断整个评估都无法进行，不得猜测。

## Quality Checklist

输出前必须检查：

- 是否只围绕日常信息过滤；
- 是否区分了长期重要信号和短期噪音；
- 是否没有给出交易指令；
- 是否没有扩展为周报、组合复盘或机会报告；
- 是否没有新增投资框架；
- 是否标记了信息不足之处；
- 是否说明了需要继续验证的假设；
- 是否为每个写入的观察候选使用 canonical IOS状态 建议动作，且没有把它与优先级或价格位置混用；
- 对存在活跃 入场计划 的条目，是否只做了评估、没有创建/修改/重新估算计划本身的任何字段；
- 执行状态 的判定是否严格按照固定优先级顺序（失效/复核触发 > 不追高条件 > 技术确认条件 > 默认）；
- 切换 报告摘要 前是否已回读所有暂存的 执行状态，确认每个非空值都严格属于五值白名单、没有 `进入区间`/`不追高`/`暂停并复核`/`无 active 计划` 等别名；
- 入场计划估值锚点 是否原样复制自所引用计划版本，没有改写或概括；
- 遇到并列最高版本的活跃计划行时，是否按"无法可靠确定"处理并写入报告待办、且没有同时设需要复核为真；
- 活跃计划可靠选定但评估数据缺失时，是否仍然写入了 入场计划ID/入场计划估值锚点，而不是连同执行状态一起清空；
- 是否保持模型中立；
- 是否可以被 Agent 层稳定调用；
- 是否符合 IOS 的长期投资顺序。
