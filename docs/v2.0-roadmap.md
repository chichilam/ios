# Investment Operating System v2.0 Roadmap

> **状态说明（`v2.0.0` 发布后追加）**：本文档是前瞻性的架构蓝图，不是实现状态报告。`v2.0.0`（见
> `CHANGELOG.md`）已交付 Agent Runtime dry-run 脚手架、Research Store/Session/Workflow 框架、
> EDINET/SEC providers 与 28 个 workflow——大致对应下方 Milestone 1 与 Milestone 2（Research Engine）
> 的范围。MCP Integration（Epic 2 的真实连接器部分）、Knowledge Base（Epic 4）、Portfolio Operating
> System（Epic 5）与完整 Evaluation Framework（Epic 6）均**尚未实现**，仍是未来版本的路线图，不属于
> `v2.0.0`。今天可以实际运行什么，见 [`docs/usage/`](usage/) 与 [`docs/README.md`](README.md)。

## 愿景

将 Investment Operating System 从文档驱动的投资框架，升级为 AI 原生的投资研究平台。

v1.0 定义了投资哲学、工作流规范和 Agent 编排规格。

v2.0 让这套规范真正可执行：连接真实数据源、运行可调度的 Agent、积累可查询的知识库、支持实际的组合决策。

---

## 架构演进

### v1.0 架构（已完成）

```
Book
↓
Prompt Suite
↓
Examples
↓
Agent（规格层，不可执行）
```

v1.0 是一套完整的规范体系。Agent 层仅定义编排规格，不实现实际执行。

### v2.0 架构目标

```
Book（知识层，保持冻结）
↓
Prompt Suite（工作流层，按需扩展）
↓
Agent Runtime（执行层，新增；对外仅暴露 Tool / Data Provider Interface）
↓
Research Engine（研究执行层，新增；对外仅依赖 Research Store Interface）
↓
Knowledge Base（知识积累层，新增；实现 Research Store Interface 的完整版本）
↓
Portfolio Operating System（决策支持层，新增）
```

详细的接口层拆分见下方「依赖关系」。

横切关注点：

```
MCP Integration（数据与工具连接层）
Evaluation Framework（质量保证层）
```

## Epic 定义

### Epic 1：Agent Runtime

**目标**：让现有 Agent 规格从可读文档变为可执行单元。

**范围**：
- 实现 Planner：根据输入选择正确的 Agent 和 Prompt
- 实现 Research Agent：调用 Prompt Suite 执行研究任务
- 实现 Portfolio Agent：支持组合层决策流程
- 实现 Reviewer：对 Agent 输出执行结构化审查
- 实现 Critic：识别输出中的逻辑问题和遗漏
- 实现 Memory：跨会话保留研究上下文和决策历史

**交付物**：
- Agent 执行框架规格
- Tool / Data Provider Interface：Agent 调用外部数据和工具的抽象接口（不绑定具体实现）
- 各 Agent 的输入/输出接口定义
- Human Review 触发规则
- 错误处理和回退策略

**依赖**：Prompt Suite v1.0（工作流定义）

Agent Runtime 核心框架不依赖 MCP Integration 的具体实现。它只依赖自己定义的 Tool / Data Provider Interface。MCP Integration 是这个接口的一种实现方式，两者可并行开发。

---

### Epic 2：MCP Integration

**目标**：通过 MCP 协议连接外部工具和数据源，为 Agent Runtime 提供真实输入。

**范围**：
- GitHub：读取研究笔记、Issue、PR 作为上下文
- Notion：读写投资笔记、研究数据库、决策日志
- Gmail / Google Calendar：读取公司公告、会议安排、财报日历
- 市场数据提供商：实时价格、财务数据、新闻
- OpenAI / 模型提供商：可替换的模型调用层

**交付物**：
- 各 MCP 连接器的接口规格
- 数据标准化格式（输入 Agent 前的统一结构）
- 认证和权限边界定义
- 模型中立调用层规格

**依赖**：Agent Runtime 的 Tool / Data Provider Interface 定义（不依赖 Agent Runtime 完整实现）

MCP Integration 实现 Agent Runtime 定义的接口，为其提供真实连接器。两者是并行的基础 Epic：接口定义完成后即可分别推进，在 Milestone 1 组合成端到端执行。

---

### Epic 3：Research Engine

**目标**：构建系统化的研究执行能力，覆盖个股、行业、宏观和 IPO 研究。

**范围**：
- 个股研究工作流：财报分析、估值更新、竞争分析
- 行业研究工作流：产业链追踪、格局变化、催化剂识别
- 宏观研究工作流：利率、汇率、流动性追踪
- IPO 研究工作流：招股书分析、定价评估、上市后跟踪
- Watchlist 工作流：持续追踪待研究标的

**交付物**：
- 各研究类型的 Prompt 扩展（在 Prompt Suite 框架内）
- 研究输出的标准结构
- 研究任务优先级规则
- Research Store Interface：研究输出的最小存储接口（读写研究记录，不含检索、图谱等能力）

**依赖**：Agent Runtime、MCP Integration

Research Engine 只依赖一个最小的 Research Store Interface，不依赖完整 Knowledge Base。这个接口在 Milestone 2 由简单存储实现（例如文件或单表），在 Milestone 3 由完整 Knowledge Base 替换底层实现，接口本身保持不变。

---

### Epic 4：Knowledge Base

**目标**：积累、索引和检索投资研究知识，让 Agent 能够引用历史研究和决策。

**范围**：
- 公司数据库：基本面快照、历史财报、分析历史
- 投资论点库：已记录的买入/卖出/持有论点
- 决策历史：每次实际决策的输入、输出和结果
- 知识图谱：公司、行业、宏观因素之间的关联
- 交叉引用：研究结论与 Book 原则的对应关系

**交付物**：
- 知识库数据模型
- Research Store Interface 的完整实现（替换 Milestone 2 的最小存储）
- 检索接口（Agent 如何查询历史知识）
- 知识图谱
- 知识老化策略（旧数据的处理规则）

**依赖**：Research Engine（通过 Research Store Interface 产生知识）、Agent Runtime（检索知识）

---

### Epic 5：Portfolio Operating System

**目标**：在研究基础上支持组合层决策，包括仓位追踪、配置建议和风险监控。

**范围**：
- 仓位追踪：当前持仓、成本、权重、盈亏
- 配置引擎：基于 Book 原则的仓位建议
- 买入/卖出决策支持：触发条件、决策清单、执行记录
- 现金部署：闲置资金的配置时机和规则
- 风险监控：集中度、相关性、下行风险追踪

**交付物**：
- 组合数据模型
- 配置决策规则（基于 Book 第四章、第五章、第六章）
- 买卖决策 Prompt 扩展
- 风险指标定义和阈值

**依赖**：Research Engine、Knowledge Base、Agent Runtime

---

### Epic 6：Evaluation Framework

**目标**：系统化评估 Prompt 质量、Agent 输出质量和研究结论准确性。

**范围**：
- Prompt 评估：输出结构一致性、规则遵循率、信息完整度
- Agent 评估：任务完成率、Human Review 触发准确性、错误率
- 输出评分：研究结论质量的结构化打分
- 回归基准：防止 Prompt 或 Agent 变更引入退化
- 历史对照：将研究结论与后续实际结果对比

**交付物**：
- 评估指标体系
- 基准测试数据集（基于 Examples 扩展）
- 自动评估 Prompt
- 回归测试工作流

**依赖**：Agent Runtime、Research Engine、Knowledge Base

Evaluation Framework 的最小子集（输出结构校验、任务完成率追踪）从 Milestone 1 开始随每个阶段同步交付，而不是等到 P6 才启动，以降低前四个阶段的回归风险。P6 交付的是完整指标体系、基准数据集和历史对照能力。

## 优先级排序

| 优先级 | Epic | 理由 |
| --- | --- | --- |
| P1 | Agent Runtime | 其他所有 Epic 的执行基础；v1.0 Agent 规格在此变为可运行。核心框架只依赖自定义接口，可与 MCP Integration 并行开发 |
| P2 | MCP Integration | 实现 Agent Runtime 定义的 Tool / Data Provider Interface；与 P1 并行推进，在 Milestone 1 组合为端到端执行 |
| P3 | Research Engine | 核心使用场景；直接交付投资研究价值 |
| P4 | Knowledge Base | 让研究积累可查询；支撑 Research Engine 和 Portfolio OS |
| P5 | Portfolio Operating System | 依赖研究质量和知识积累；后置实现风险更低 |
| P6 | Evaluation Framework | 贯穿整个 v2.0；可在各 Epic 落地后逐步完善 |

## 里程碑

### Milestone 1：可执行 Agent（P1 + P2）

目标：现有 5 个 Agent 规格可在真实数据上运行。

- Agent Runtime 核心框架 + Tool / Data Provider Interface
- MCP Integration：Notion + 市场数据（最小集），实现上述接口
- Daily Agent、Weekly Agent 可端到端执行
- Human Review 流程可操作
- 最小评估与回归：Prompt 输出结构校验、Agent 任务完成率追踪（Evaluation Framework 的最小子集，随每个 Milestone 同步扩展）

### Milestone 2：研究引擎上线（P3）

目标：系统化个股和 IPO 研究可执行。

- Research Engine：个股研究、IPO 研究工作流
- Prompt Suite 扩展（财报分析、估值更新）
- Research Agent 可调用 Research Engine
- Research Store Interface 最小实现（研究输出结构化存储，接口在 Milestone 3 由完整 Knowledge Base 替换底层实现）

### Milestone 3：知识积累（P4）

目标：研究结论可持久化、可检索。

- Knowledge Base：公司数据库、投资论点库
- Agent 写入和检索接口
- 决策历史追踪

### Milestone 4：组合决策支持（P5）

目标：组合层买卖决策有系统支持。

- Portfolio Operating System：仓位追踪、配置引擎
- 风险监控基础指标
- 买卖决策清单自动化

### Milestone 5：评估体系完善（P6）

目标：全系统质量可度量、可回归。

Evaluation Framework 不是到 Milestone 5 才开始建设：最小评估与回归从 Milestone 1 起随每个阶段同步扩展。Milestone 5 交付的是完整体系：

- 完整 Prompt 评估、Agent 评估指标体系
- 基准测试数据集（覆盖 Milestone 1-4 的所有场景）
- 回归基准建立
- 历史对照工作流

## 依赖关系

依赖关系按接口层拆分，避免 Epic 之间互相依赖对方的完整实现：

```
Book + Prompt Suite
        ↓
Agent Runtime（核心框架 + Tool / Data Provider Interface）
        ↓ 实现接口
MCP Integration（Adapters）
        ↓ 组合
End-to-End Agents（Milestone 1）
        ↓
Research Engine（依赖 Research Store Interface，最小实现）
        ↓ 接口不变，替换底层实现
Knowledge Base（完整数据模型、检索、知识图谱）
        ↓
Portfolio Operating System
```

Evaluation Framework 横切所有层：最小子集从 Milestone 1 起同步交付，完整体系在 Milestone 5 完成。

---

## 非目标

v2.0 不包括：

- 改写 Book 投资哲学
- 修改 Prompt Suite v1.0 已冻结内容
- 实现全自动交易执行（所有投资行动仍需 Human Review）
- 实时新闻聚合或社交媒体分析
- 多用户或团队协作功能
- 移动端应用
